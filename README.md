# SIGNAL ROOM v0.4 — Solo Incident Lab (исправленная версия)

Практическая одиночная мини-игра по реагированию на вымышленный киберинцидент. **Командного режима больше нет.** В отличие от предыдущей версии, здесь нет вопросов с тремя вариантами ответов: ты работаешь в локальной учебной системе — исследуешь события, делаешь **настоящие SQL SELECT-запросы в SQLite**, вводишь операционные команды, изолируешь подозрительную сессию, откатываешь плохой релиз, перезапускаешь сервис и оформляешь отчёт.

## Как запустить на Mac

1. Распакуй `Signal-Room-polished.zip` и открой папку `Signal-Room` в VS Code (или перейди в неё через терминал).
2. Открой `Terminal → New Terminal`.
3. Выполни `python3 server.py` (Python 3.9+; установка библиотек **не нужна**).
4. Игра сама попробует открыть браузер. Если нет — открой **http://127.0.0.1:3080**.
5. Чтобы остановить сервер, нажми `Control + C`.

Если появился `Address already in use`, запусти `python3 server.py --port 3081` и открой http://127.0.0.1:3081.

Не открывай `static/index.html` двойным кликом: приложение получает состояние от локального игрового сервера.

## Режимы игры

При запуске выбери один из режимов:

- **Все атаки** — все шесть типов security-сигналов входят в сценарий.
- **Случайный набор** — для каждого прохождения выбираются случайные 3–6 типов.

В обоих режимах нужно исследовать события, закрепить все сигналы выбранного набора и локализовать активные угрозы командой `security contain <SEC-ID>`. Задержка усиливает последствия, а неверная команда снижает оценку.

## Что делать в игре

Ты — аналитик в вымышленной компании **ASTER**. В 10:21 начались проблемы с входом в рабочий сервис; SOC увидел необычную активность с одного аккаунта. Причина может быть не одна. Твоя цель — **провести техническое расследование**:

- Начни с `help`, `status`, `ls /var/log`, `cat /var/log/auth.log`, `logs security`, `grep ERROR /var/log/app.log`, `db tables`.
- Исследуй таблицы SQLite (например, `sql SELECT * FROM sessions;`), найди связанные события и записи.
- Для дополнительных учебных сигналов используй `logs security` или `sql SELECT * FROM security_events;`: там есть детектированные признаки spoofing, попытки повышения привилегий, фишинга через почтовый шлюз, MAC flooding, аномалий Wi-Fi handshake и MFA fatigue. Это вымышленные события для расследования; симулятор не запускает атаки и не содержит команд для них.
- Прикрепи ключевые события командой `evidence pin <ID>` и запиши своё наблюдение через `case note <текст>`.
- Используй командные инструменты, чтобы остановить злоупотребление и восстановить сервис.
- Проверь результат: только после этого `case close` закроет дело.

**Важное:** игра не выполняет настоящие команды ОС и не соединяется с какими-либо аккаунтами, внешними серверами или БД. SQL SELECT выполняется **по реальной локальной SQLite-базе**, которая содержит только тестовые данные. Операции изменения статуса сессий, аккаунтов и сервисов реализованы игровым движком, а не ОС.

Оценка — **игровая**, не сертификат. Время изменяется при оперативных действиях, а не по реальным часам. Если злоумышленная сессия остаётся активной достаточно долго, в симуляции происходят дополнительные выгрузки. Правильное полное прохождение теперь позволяет набрать 90–100 баллов. Состояние сохраняется при **перезагрузке страницы**, пока работает тот же процесс `server.py`; перезапуск Python-сервера сбрасывает прогресс.

## Структура

- `server.py` — HTTP-сервер, SQLite, сценарий и командный движок (Python стандартная библиотека)
- `security_events` — безопасная телеметрия по детектированным угрозам и рекомендуемым защитным действиям
- `static/index.html` — интерфейс
- `static/style.css` — дизайн
- `static/app.js` — фронтенд
- `tests/test_game.py` — автоматические проверки сценария
- `DESIGN.md` — идеи развития игры и продукта

Игра запускается только на `127.0.0.1` и предназначена для одного локального пользователя. **Не публикуй этот сервер в интернете** и не вводи реальные пароли/персональные данные.

## Что исправлено в v0.4

- Тест полного прохождения обновлён под 6 security-сигналов; проверяются оба режима.
- Исправлены повторные containment-действия: уже заблокированные или изолированные события не штрафуются.
- Зафиксированы цели игры и сбалансированы штрафы за время; результат после закрытия дела больше не меняется.
- Исправлены SQL-ответы с BLOB-значениями и ограничен размер отдельных значений.
- Ужесточена обработка ошибочных HTTP/JSON-запросов, запрещены запросы с чужих Origin, отключено кэширование файлов интерфейса.
- После обновления страницы восстанавливается текущая сессия и история терминала; меню новой игры можно закрыть без сброса.
- Исправлен счётчик писем и отображение названий журналов; чек-лист теперь виден и на узких экранах.

## Проверка

Из папки проекта выполни:

```bash
python3 -m unittest discover -s tests -v
```

Должно пройти 21 тест. Также можно проверить синтаксис JavaScript командой `node --check static/app.js`, если установлен Node.js.

## Как обновить общий GitHub-репозиторий

Если у тебя есть доступ collaborator к `slaidayZ/Signal-Room`, **не стирай .git** в локальном клоне и не загружай в GitHub вложенный ZIP вместо исходников. Лучше:

1. Склонируй проект в **новую папку**: `git clone https://github.com/slaidayZ/Signal-Room.git` (или обнови уже клонированную папку командой `git pull`).
2. Скопируй содержимое этой версии (`server.py`, `static/`, `tests/`, `README.md`, `DESIGN.md`, `CHANGELOG.md`, `preview.png`) в корень клонированного репозитория. Не копируй чужие файлы и скрытую `.git`.
3. Запусти тесты и проверь игру, затем `git status` и `git diff`.
4. Если всё правильно: `git add .`, `git commit -m "Polish Signal Room v0.4"`, `git push origin main`. При работе в команде безопаснее сначала создать ветку и Pull Request.
5. Тиммейт выполнит `git pull` у себя в рабочей папке (на GitHub изменения появятся сразу после push/merge).

Перед перезаписью общих файлов предупреди тиммейта, если он параллельно изменяет проект.
